# 1-5.TS-ROUNDTRIPPED.sav

**Tower:** 1-5 Tiny Tower
**App version:** v0.7-455
**Base file:** `data/saves/iestyn.2026.08.28/1-5.sav`
**Records:** all 36, none replaced
**Byte-identical to the base:** **No** — and that is the point of the test.

## What it tests

Whether the game's loader accepts a `.sav` whose zlib streams were produced by
**Node's** deflate rather than Love2D's.

SPEC-006 §6: our TypeScript codec reproduces the *payload* byte-for-byte on all
326 records in the corpus, but Node's `deflateSync` matches the game's
compressed bytes on only 82 of them. The difference is entirely in the
compressor's choices, not in the data.

This file was produced by parsing `1-5.sav` and re-emitting it whole:

```
npx tsx tools/sav/resave.ts data/saves/iestyn.2026.08.28/1-5.sav \
                           data/saves/tests/1-5.TS-ROUNDTRIPPED.sav
```

The tool asserts before writing that all 36 records keep their name, timestamp
and exact entry list, and that every payload inflates to the original bytes. So
**no route in this file has changed**; only the compression has.

| | |
|---|---|
| original | 26 456 bytes |
| re-emitted | 26 511 bytes (+55) |
| payloads identical | 36 / 36 |

## Expected outcome

**Loads normally**, with all 36 saves present and replaying as before. `inflate`
is specified to accept any valid `deflate` stream, and both implementations are
long-standing and well tested.

## Why it matters

If it loads, save *writing* can move to TypeScript now, and SPEC-006 §6 is
downgraded from a limitation to a note: byte-exactness against an original stops
being the acceptance test for a writer, replaced by "the payload matches and the
game loads it".

If it does **not** load, the game is doing something stricter than inflating —
comparing a length, or a checksum computed elsewhere — and that is worth knowing
precisely, because it would also constrain any future writer.
