## What it tests

Hypothesis B: stepping ONTO a Pop-Up Wall is encoded; stepping off is not, unless the step off causes another state change.

Pair 1 steps onto Pop-Up Wall (4,11) from Empty (3,11). Pair 2 steps onto Pop-Up Wall (6,8) from Empty (5,8). Pair 3 steps off (6,8) onto the Light Key at (7,8) - encoded because the key is consumed. Pair 4 kills the Slime at (7,7). Compare undo/redo behaviour against POPUP-TO-KEY (hypothesis A).

## Payload

`(floor, x, y)`, 1-based, origin top-left:

```
  1. (3, 3,11) -> (3, 4,11)
  2. (3, 5, 8) -> (3, 6, 8)
  3. (3, 6, 8) -> (3, 7, 8)
  4. (3, 7, 8) -> (3, 7, 7)
  current position: (3,7,7)
```

## Expected result

Loads, and undo/redo matches normal play: undo from the key lands ON the pop-up wall; a further undo lands on the Empty tile before it; a further undo lands BEFORE the first pop-up wall, not on it.
